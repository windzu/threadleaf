# Threadleaf 项目愿景

## 背景

Obsidian 是一个以页面为中心的工作空间。用户通过切换 Markdown 笔记、Bases、Canvas、PDF 和 Workspace Leaf 在知识之间移动。

多数 Obsidian Agent 插件却采用以聊天为中心的模型：

- Agent 固定在侧边栏；
- 多个对话以聊天 Tab 组织；
- 切换笔记不会自动切换对应对话；
- 用户必须同时维护页面导航和聊天导航。

这会产生四类问题：

1. **双重导航**：切换页面后还要手动寻找对话。
2. **上下文错位**：当前可见页面和 Agent 实际处理的页面可能不同。
3. **对话难以查找**：任务标题通常不能直接表达它属于哪个页面。
4. **人为工作集限制**：聊天 Tab 数量限制迫使用户主动管理本应自动解析的状态。

Notion 展示了更自然的交互模型：Agent 默认关联当前页面，页面切换后默认上下文自动变化，已有工作可以恢复，其他页面则通过显式引用加入。

Threadleaf 的目标是把这种「页面原生」的 Agent 体验带到 Obsidian。

## 使命

让当前 Obsidian 页面自然成为 Agent 对话的归属位置。

当用户不再需要思考「应该切换到哪个 Agent Tab」，而只需要打开页面、唤起 Agent 并继续该页面的工作时，Threadleaf 才算成功。

## 核心产品模型

### 主资源

每条页面对话只有一个主资源：

- 第一阶段是 Markdown 笔记；
- 后续扩展到 Base、Canvas、PDF 和其他 Obsidian View。

主资源决定这条对话属于哪个页面。

### 附加资源

通过 `@` 或附件添加的其他文件只是额外上下文，不会改变对话归属。

### 页面对话状态

一个页面可以拥有多条对话，但始终记录最近使用的对话。打开 Threadleaf 时：

1. 优先恢复该页面最近使用的对话；
2. 如果不存在，则显示属于该页面的空白新对话。

### 全局历史

全局对话历史用于搜索、恢复和跨页面查看，但不是主要导航方式。页面内对话历史优先显示。

## 目标交互

### Agent 关闭时

- 页面右下角显示悬浮入口。
- 入口可以表达「运行中」「已完成」「等待审批」等后台状态。
- 页面可见并不意味着必须提前加载 Conversation Runtime。

### Agent 打开时

- 展开 Obsidian 原生右侧 Workspace View。
- 解析当前有效内容页面。
- 显示该页面最近的对话或页面级空白草稿。
- 当前页面作为稳定的主上下文展示。

### 切换页面时

- 保存离开页面的输入草稿。
- 自动恢复新页面的对话。
- 原页面后台任务继续运行。
- 旧的异步加载结果不能覆盖新页面。

### 新建对话时

- 在当前页面下创建一条新对话。
- 新对话成为该页面最近使用的对话。
- 旧对话仍保留在页面内历史中。

## 核心目标

### G1：页面原生路由

根据当前 Obsidian 内容 Leaf 自动解析正确的 Agent 状态。

### G2：对话连续性

可靠恢复页面最近对话、输入草稿、流式状态和页面归属。

### G3：后台执行

页面切换不能取消原页面任务，并提供清晰的完成和审批提醒。

### G4：复用 Provider 能力

复用成熟的 Claude、Codex、Tool Call、权限和历史协议，不重新实现 Agent Runtime。

### G5：Local-first

页面和对话的映射、元数据保存在 Vault 或其他用户可控制的本地存储中。

### G6：符合 Obsidian 使用习惯

正确处理 Workspace Leaf、主题、快捷键、文件重命名、多分栏和弹出窗口。

## 第一阶段非目标

- 覆盖所有 Obsidian View 类型。
- 支持移动端。
- 云端账号和托管式对话存储。
- 多人实时协作。
- 视觉上逐像素复制 Notion。
- 重新实现 Provider 原生 Runtime。
- 保持无限数量的同时活跃 Runtime。

## 推荐技术路线

第一阶段 fork Claudian，并保留：

- Provider-neutral Runtime；
- Claude 和 Codex Provider；
- 流式输出与审批；
- Tool、Diff 和消息渲染；
- Conversation 持久化；
- `@` 引用和 Inline Edit。

重点替换或重构：

- `TabManager`；
- 聊天 Tab Bar；
- Active Conversation 恢复；
- `currentNote` 的语义；
- Chat View 生命周期；
- 后台 Runtime 管理。

新增的交互层应包含：

- `PageContextResolver`；
- `PageConversationRouter`；
- `PageAgentIndex`；
- `RuntimeCoordinator`；
- 页面级草稿持久化；
- 悬浮入口状态管理。

## 第一阶段范围

- macOS Desktop；
- 单个 Obsidian Vault；
- Markdown 页面；
- 单主窗口；
- 页面右下角悬浮入口；
- 原生右侧 Agent View；
- 页面级新对话和历史对话；
- 页面历史与全局历史；
- `@` 引用；
- Claude 和 Codex；
- 页面切换期间保持后台 Streaming。

## 第一阶段验收标准

- 在任意页面打开 Agent，都能显示预期的页面对话。
- 在两个页面之间切换，不需要手动切换对话。
- 页面切换不会取消正在执行的任务。
- 输入草稿在多次页面切换后不丢失。
- 页面重命名后仍能找到原有对话。
- 主页面与 `@` 附加上下文在界面和语义上明确区分。
- 用户日常工作时不需要操作聊天 Tab Bar。

## 长期方向

Threadleaf 可以从页面对话工具逐步演进为页面原生的 Agent 工作层：

- 根据页面类型提供建议动作；
- 为 Markdown、Bases、Canvas、PDF 提供专属能力；
- 后台任务中心；
- 页面级对话摘要；
- 建立页面、任务与 Agent 结果之间的持久关系；
- 基于用户自有存储实现可选的跨设备同步。

Threadleaf 的长期差异化不在于接入某个特定模型，而在于建立一种稳定的交互契约：

> Agent 始终知道用户正在什么地方工作，并能恢复属于那个页面的工作。
